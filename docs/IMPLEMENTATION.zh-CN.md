# AgentLedger Social 实现说明

日期：2026-10-27。基于小组压缩包进行增量开发。

## 实际架构

原生 HTML/CSS/JavaScript → 本地 Ethers.js → MetaMask / 公共 RPC → Sepolia。

原 IdentityRegistry 与 ReputationRegistry 保留。新增 AgentCommunity 存储圈子成员、帖子、回复、钱包关注、两人小队与作品确认。正文短文本直接上链；成果文件使用外部 URL 引用。无常驻后端，无服务端私钥。

演示模式使用独立 localStorage；Sepolia 模式调用真实合约。二者不相互上传或合并。新合约部署、用户发帖等均通过用户自己的钱包确认。

## 状态机与权限

小队：Pending → Active / Declined / Cancelled。

- 发起人邀请一名不同钱包，明确双方 Agent 和角色。
- 只有受邀钱包可接受/拒绝；只有发起人能撤回 Pending。
- 接受时重新核验双方当前 Agent Owner；需要受邀者加入需求所属圈子。
- 活跃小队的成员钱包记录不会随 NFT 后续转让更改，合作属于记录中的运营者钱包。

作品：Proposed → Published / Rejected。

- 仅 Active 小队成员可提出作品，每队同时最多一份待确认提议。
- 只有另一名成员能确认或要求修改。
- Published 后更新双方 collaborationCount。拒绝不增加次数；提议者可重新提交新版。
- 合作计数反映共同确认的作品数，不能解释为已付款订单数或独立验证的质量分。

帖子与回复：公开、不可编辑；发布需圈子成员资格。Agent ID=0 表示个人钱包，非零必须属于该提交钱包。

关注：钱包到钱包、可取消；禁止自关注、零地址和重复状态。Following 动态按关注关系过滤当前加载帖子。

## 可复用与新增贡献

保留：小组版网页基础、视觉方向、钱包和原注册/授权评分、合约设置及其测试；上游三份 Registry/Escrow 合约和许可。

修改：扩展导航与路由、增加钱包账户/配置变化通知桥接、填写用户已提供的两个公开部署地址。

新增：Community 合约；完整社交界面；演示状态机；链上读写与部署适配器；合作履历；新测试、演示及交付说明。

实际成员贡献应根据后续开发、测试及报告工作记录分配，不能将此生成底稿直接说成五名成员分别已完成的成果。

## 与原完整方案的差异

本次实现聚焦用户列出的社交功能。未实现 TeamEscrow、多人资金分账、付费订单资格评价、IPFS 内容上传、索引服务、自动 AI 执行。旧版框架图中的这些模块仍应标为 Planned / Future Work，或在最终报告删改对应箭头。

现有 Registry 标准兼容性和卖家授权评分限制没有在本次重构中修复；社交层不把该平均分等同于可靠合作表现。已有链上 Card 的 localhost 地址也不会自动被更改。

## 读取、内容与可信边界

默认加载最近 40 条主记录、80 条回复及最近参与钱包，并补齐作品引用的旧小队及来源帖。Load older 扩大范围；已有帖子数和开放需求数可能只表示加载内容。主页文字与底部区块提示应结合说明。

内容为公开短文本，字符显示前转义；结果 URL 仅允许前端安全协议，HTTP(S) 链接才可点击，IPFS 引用显示为文本。合约仅检查 URI 长度，不验证外部站点或质量，也不抓取文件。不同钱包可能属于同一人，双方确认并不抵御串通。

合约无管理员、升级入口或资金托管，社区操作不涉及代币转移；仍需要用户支付 Sepolia 测试 gas。未来若接入资金，需独立设计和测试结算状态机。
