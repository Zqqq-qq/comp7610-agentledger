# 身份 → 服务交易 → 评价：网页完整操作指南

角色固定为 A = 客户 / 付款人 / 评价者；B = 服务方 / 身份所有者。两者需要 Sepolia ETH 付 gas。所有交易需你自己在 MetaMask 确认。本指南使用现有后端合约，不需要 Foundry 或 Git Bash。

## 1. 启动网页

在项目根目录打开终端（需 Node.js 20+），运行：

```powershell
node scripts/serve.mjs
```

保留该窗口。在安装 MetaMask 的 Chrome 或 Edge 打开 http://127.0.0.1:8091 。代码更新后按 Ctrl+F5 刷新。端口被占用时，关闭旧的本项目服务器后重启，或设置 PORT 环境变量指定另一个端口。

## 2. 填写四个已部署的公开地址

点击右上角 Contracts，依次填入 IdentityRegistry、ReputationRegistry、JobEscrow、MockUSDC 地址。RPC 使用默认 PublicNode；失败可试 dRPC backup。点击 Verify & save contracts。

地址来自 Remix 的 Deployed Contracts。不要填 A/B 钱包地址。四份合约均应在 Sepolia，信誉合约与托管合约的 identity() 都要指向填写的身份合约。

如果尚未部署 JobEscrow，使用原 JobEscrow.sol，构造参数填 IdentityRegistry 地址；MockUSDC 使用原运行包中的 MockUSDC.sol，无构造参数。公开部署记录见 project/DEPLOYMENTS.md；完整关联操作见 ESCROW_INTEGRATION.zh-CN.md。部署过的合约可直接复用。

如果只填两份登记合约，原有功能仍可使用，任务托管页保持未配置状态。填写托管时，JobEscrow 和 MockUSDC 必须同时填写。源码默认没有你的真实地址，需要在本浏览器重新配置；也可将公开地址写进 web/config.js。

## 3. 连接并选择 B，注册身份

1. 点击 Connect wallet，允许本网站连接 A/B。
2. 点击右上角钱包按钮，查看 Active account 下拉框，选择 B。以完整地址核对账户；若 B 不在列表，点 Choose another account，在 MetaMask 权限窗口允许 B。
3. MetaMask 网络选择 Sepolia；页面出现错误网络提示时点 Switch to Sepolia。
4. 进入 Register an agent。填写已有 Agent Card URI，也可点 Use the local example card 使用本机示例。
5. 点击 Register on-chain，确认钱包交易，等待网页显示实际 Agent ID。
6. 在 Agent registry 核对 Owner = B。已有 B 身份时直接使用，不必重复注册。

刚注册的 B 地址和实际 ID 会预填到 Task escrow 创建表单。公共演示若需他人访问 Agent Card，应使用公开 HTTPS / IPFS URI，本机 localhost URI 只能本机访问。

## 4. 选择 A，准备测试代币

1. 在网页钱包菜单 Active account 选择 A。
2. 进入 Task escrow。顶部 ACTIVE WALLET 必须是 A 的完整地址。
3. 展开 Need test mUSD?。
4. 点击 Mint 100 test mUSD，钱包确认，等待成功。
5. 点击 Refresh balances，查看 A 的余额。如果之前余额为 0，现在显示 100.0 mUSD。重复铸币会累加。

这里是测试 mUSD，没有货币价值。Mint 交易仍消耗 Sepolia ETH。网页中的余额查询不依赖 MetaMask 是否导入了该代币。

## 5. A 授权并创建付款

在 Create & fund a task 填写：

- Provider B wallet address：B 的完整地址。
- Provider Agent ID：B 的实际 Agent ID。不要使用 A 的身份；0 表示跳过身份关联，不适合展示完整身份关联流程。
- Payment in mUSD：**1**。网页使用人类可读单位，会自动转换为合约的 1000000。不要填 1000000，否则表示一百万 mUSD。
- Submit within (minutes)：**60**。
- Review window (seconds)：**600**。

1. 点击 **1. Approve mUSD**，钱包核对发送人为 A 并确认。等待 Approval confirmed。授权的是本次金额，spender 是配置的 JobEscrow；已有足够额度时会提示不需要再发授权交易。
2. 点击 **2. Create & pay**，再次确认交易并等待成功。网页从最新区块时间自动计算截止时间，不需要 PowerShell 手算时间戳。
3. 记录成功提示中的实际 **Task #ID**。网页从本笔 JobCreated 事件解析，不依赖 nextJobId 猜测。
4. Deliver & settle 面板会自动加载该任务，状态应是 **1 · Funded**。
5. 核对 Client A、Provider B、Agent ID、token、amount、deadline。A 余额减少 1 mUSD；资金进入 JobEscrow，此时 B 尚未收款。

每笔任务的批准额度会被创建消耗，下一个任务重新检查 / 授权。截止时间按创建时的最新区块计算；钱包确认拖得太久而过期，需要重新创建并设置更长时间。

## 6. B 提交交付摘要

1. 网页钱包菜单选择 B。不要只看 MetaMask 当前显示账户；核对网页 ACTIVE WALLET。
2. 同一页面保持当前任务；如果换浏览器或刷新后面板没加载，在 Job ID 输入实际任务 ID，点 Load / refresh。
3. 核对任务状态为 Funded，Provider 是 B。
4. 选择一种摘要输入方式：
   - 点 Use demo digest：填入 0x 后 64 个 1，仅用于演示状态机，不是实际成果哈希。
   - 点 Hash a local file：选择实际交付文件，浏览器计算 Keccak-256，最大 20 MB。文件不会上传，仍需另外分享交付物。
   - 直接粘贴已有非零 bytes32：0x 后 64 位十六进制字符。
5. 点击 **B · Submit delivery digest**，钱包确认，等待成功。
6. 状态应变为 **2 · Submitted**，任务详情出现 submittedAt 和 digest。资金仍在托管合约中。

A 的账户不能提交。超过提交截止时间也不能提交。摘要不能证明质量，系统不具备自动质量验收功能。

## 7. A 验收并支付给 B

1. 网页切回 A。
2. 必要时点击 Load / refresh，确认 Submitted。
3. 点击 **A · Accept & release payment**，确认钱包交易。
4. 等待状态变成 **3 · Completed**。
5. 查看任务详情 CURRENT TOKEN BALANCES，B 应比付款前增加 1 mUSD。托管总余额包括其他任务，不能据总余额断言本任务未结算。

A 不需要等待 600 秒才能验收付款。该 600 秒用于 B 提交后、A 不验收时的超时领取。Completed 后同一任务不能重复支付或退款。

## 8. 从已完成任务进入评价授权

1. 在任务面板点击 **Continue to feedback authorization**。只有 Completed 且 providerAgentId 非零时可用。
2. 页面跳转 Reputation → Authorize a reviewer，自动填入 B 的 Agent ID 和客户 A 的地址。
3. 选择 **B**，核对 Agent ID 与 Reviewer wallet address = A。
4. 点击 Sign authorization，在 MetaMask 签名。签名不消耗 gas。
5. 复制生成的完整 JSON。
6. 点击 Continue to submit feedback，或切换到 Submit feedback 标签。
7. 网页钱包切换为 **A**，将 JSON 粘贴到 Authorization JSON，评分例如 90，标签可填 demo-service。
8. 点击 Submit feedback on-chain，钱包确认，等待成功。
9. Agent registry → Refresh，展示 B 的平均分与评价数量，以及成功交易链接。

“继续评价”只是预填现有表单。评价合约不检查 jobId，也不要求任务完成。不要声称现有系统已实现“只能由已完成任务的客户评价”。若身份所有权已经转移，需要当前 Owner 重新授权；原 B 不能再以旧身份授权。

## 9. 可选：退款与超时领取

每条路径创建一个新任务，不要复用已完成任务。

### 未提交退款

A 创建新任务，Submit within 设置 2 分钟或更长；B 不提交。等待链上时间严格超过截止时间，点 Load / refresh。A 的 Refund after deadline 按钮可用后，点击并确认交易，状态应为 **4 · Refunded**。

### 已提交超时领取

A 创建新任务，Review window 设置 60 秒；B 提交，A 不点验收。链上时间严格超过 submittedAt + 60 后，B 点 Load / refresh，再点 Claim after review window，确认后状态为 **3 · Completed**。

时间到期不会自动转账。浏览器时钟不会改变链上时间；按钮参考上一次读取的区块时间，等待后要刷新。已经 Submitted 的任务不能使用“未交付退款”，现有合约没有争议仲裁与拒收退款机制。

## 10. 演示证据与常见问题

- 保存真实 Agent ID、jobId、注册 / 创建 / 提交 / 付款 / 评价的交易链接，以及关键状态截图。
- 余额或额度不足：确认选中 A，点击 Refresh balances，必要时 Mint 或重新 Approve。
- 任务按钮灰色：检查角色、状态、链上截止时间，并点 Load / refresh。
- Provider Agent ID 不匹配：查询身份 Owner，必须与 B 地址一致。
- 页面没有钱包：使用安装 MetaMask 的 Chrome / Edge。Codex 内置预览通常没有你的钱包扩展。
- 交易已确认但刷新失败：保留成功交易链接及 ID，切换可用 RPC，再手动加载任务；不要因显示延迟重复创建或付款。
- 自动测试使用隔离测试替身，不能代替你在 Sepolia 上完成并展示的真实交易。
