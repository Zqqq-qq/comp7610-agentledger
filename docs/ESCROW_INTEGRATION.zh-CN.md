## 实现与来源

以 GitHub main `39092a5152d59abcbf37ebb11d4caa3900c06743` 为基线，接入组员提供的 `COMP7610-AgentLedger-任务托管版(1).zip` 中 escrow-core.js、escrow.js、相关界面及测试。保留社交模块、两个 Registry 配置、协作规则和测试。全部五份 Solidity 源码未修改，社区编译产物保持一致。

已实现：测试 mUSD 铸造、按本次金额授权、创建注资、从真实 JobCreated 回执取得编号、交付摘要、验收付款、未交付超时退款、已交付超时领取、完成后预填原评价授权表单。新增 escrow-links.js / escrow-link-ui.js 接入小队与需求回溯。

## 从社区进入付费任务

1. 每人使用自己的钱包。社区切到 Sepolia 模式，使用同一 AgentCommunity 地址；双方加入相同圈子、发布需求并接受小队邀请。
2. 在小队详情或需求讨论中点击 **Open paid tasks & funding / Team · paid tasks**。钱包设置中配置已部署的 JobEscrow 和 MockUSDC；两者须成对填写，托管与社区须引用同一 IdentityRegistry。
3. **Load team & linked tasks** 会读取接受后的小队，并把另一成员的钱包和记录的 Agent ID 填为服务方。付款人必须是小队成员。非零 Agent 在新订单创建时还需满足原托管合约的当前所有权检查。
4. 填金额与时限，分别确认批准、创建两笔交易。实际 jobId 来自成功回执；资金此时已在托管合约中。
5. 点击 **Publish funded task reference**，单独确认一笔社区回复交易。付款人需仍在来源圈子中。若拒签或发布失败，订单仍存在；重新加载同一 jobId 并重试发布，不要重复付款创建任务。
6. 服务方加载同一 jobId 提交摘要，客户验收放款；也可分别演示符合条件的退款和超时领取。共同作品仍独立提议和确认，确认作品不会放款。

## 关联存储与验证

关联以来源需求下的一条普通链上回复保存，前缀为 `AgentLedger escrow link v1`，JSON 字段为 version、chainId、community、postId、teamId、escrow、jobId；所有编号为十进制字符串。回复作者必须与真实订单的 client 一致。发布时用钱包身份 Agent ID 0，避免旧 Agent 转让使关联作者被误认。

读取时在同一确认区块核验网络、配置合约地址、共同 Registry、需求类型、小队来源、已接受状态、付款人属于小队、服务方为另一成员、订单中的 Agent ID、支付代币及真实订单存在。**这是前端应用对两个合约记录的验证，不是合约强制绑定**：社区合约不会理解回复中的 JSON，任意人仍可能写入无效声明；页面忽略无效引用，并将每份 escrow/job 最早一条有效引用作为标准引用。重复引用的竞争无法由原合约阻止，不能声称具有合约级唯一性。

另一设备填写同一社区、托管与代币地址及 Team ID，点击加载，即从链上回复重新读取，不依赖第一台设备的 localStorage。Task escrow 中可反向打开来源讨论。读取整个社区的前 1000 条回复；超过该上限明确报错并要求索引服务，不能将截断结果声称为完整历史。此扫描与社区动态流默认最近 80 条回复的分页独立。

## 验证结果和边界

- 本地完整自动测试：43 项通过，包括原社交测试、移植的托管前端测试、新增真实 EVM 付款/交付/结算/退款/超时领取及关联验证。
- 新增 EVM 测试执行原 Solidity 合约，验证真实余额变化、第三钱包拒绝、重复结算拒绝、无效与伪造引用过滤、重复引用规则，以及独立 reader 恢复关联。
- 编译与静态构建通过，AgentCommunity 产物无变化。托管 UI 测试仍使用测试替身；EVM 测试单独标识，不混同为 Sepolia 成功证据。
- 浏览器检查覆盖 Task escrow 页面、原 Registry 地址保留、未配置时写入按钮禁用、原社交页导航与演示小队入口、桌面无横向溢出。另使用本机临时 EVM 夹具，实测加载 Team #1、读取关联 Task #1 的真实合约数据并回溯来源讨论；该夹具不是 Sepolia 公链证据。
- **真实 Sepolia 验收尚待用户钱包执行**：没有代用户部署、签名或发送公链交易。DEPLOYMENTS.md 保留地址和交易证据待填位置。PR 的 CI 结果以实际运行链接为准。

原托管只支持一个客户和一个服务方，无多人分账、拒收退款或争议仲裁。时间到期不自动转账，需相应钱包主动调用。文件仅在本机计算摘要，不会上传实际交付物；摘要不证明质量。评价仍为原所有者授权流程，没有 jobId 资格限制。演示模式的样例不允许接入真实托管。以上均应在报告和录屏说明。
